Единая панель мониторинга и реагирования с агентами на защищаемых серверах. Собирает события безопасности, обнаруживает сканирование, перебор паролей и подозрительные сессии, блокирует источники атак и ведёт расследование инцидентов.

Ориентир по мерам защиты — требования ФСТЭК (приказы № 17, № 21, № 239), 152‑ФЗ и ИСПДн. Документ описывает реализованные функции. Формальная сертификация выполняется отдельно.

Краткое описание для поля About на GitHub:

> SIEM-панель и агенты для Windows Server и Astra Linux: сбор событий, обнаружение атак, блокировка IP, PAM, расследования и управление политиками защиты.

## Что делает система

Оператор работает в браузере. Агент ставится на сервер и сам устанавливает исходящее соединение с панелью: входящий порт на защищаемом хосте для агента не нужен. При обрыве связи агент продолжает детекцию и блокировки по последней политике и досылает накопленные данные после восстановления канала.

```
Оператор ── HTTPS ──► Панель (React + FastAPI + БД)
                          ▲
                          │ HTTPS, токен агента, опрос команд
          ┌───────────────┼───────────────┐
          │               │               │
     Windows Server   Windows Server   Astra Linux
     агент            агент            агент
```

Дополнительный канал — приём syslog по TLS (порт 6514).

## Панель

Веб-интерфейс разделён на мониторинг и безопасность. Доступ к разделам зависит от прав пользователя.

| Раздел | Назначение |
| --- | --- |
| Дашборд | Число серверов и агентов онлайн, события, тревоги за сутки, лента последних групп событий |
| Серверы | Статус агента, метрики, диагностика, перезагрузка и выключение, отключение интернета с сохранением канала до панели, файл RDP, дампы памяти процессов |
| Обновление агента | Доставка новых файлов агента на выбранные серверы, перезапуск и установка зависимостей |
| Тревоги | События и инциденты с признаком тревоги, колокольчик в шапке |
| Расследования | Разбор инцидента по серверу и хронология: разведка, доступ, привилегии, сессии, воздействие, реагирование |
| Журналы SIEM | События с группировкой одинаковых записей, фильтры, экспорт CSV, очистка по сроку хранения |
| Отчёты | Действия сотрудника панели за период и выгрузка для аудита |
| PAM / EDR | Привилегированные сессии RDP и SSH, записанные команды, завершение сессии |
| Защита серверов | Политика на каждый сервер, список заблокированных IP, снимки состояния для разбора |
| Пользователи | Учётные записи, роли и отдельные разрешения |
| Пароль и 2FA | Смена пароля и TOTP |

Роли по умолчанию: `admin`, `operator`, `auditor`, `viewer`. Поверх роли выдаются отдельные права: журналы, экспорт, серверы, питание, сеть, расследования, отчёты, обновление агента, полный доступ.

## Агент

Текущая версия агента — **2.4.0**. Одна кодовая база работает на Windows и, через слой `agent-astra`, на Astra Linux SE.

Агент регистрируется на панели, шлёт heartbeat с метриками (CPU, память, диск, соединения) и забирает команды. События уходят пакетами. Команды питания и отключения сети старше нескольких минут не выполняются.

### Что собирается

- Журнал безопасности Windows (входы, неудачи, привилегии, учётные записи) и журнал брандмауэра, включая WFP.
- Сессии RDP и SSH, команды привилегированных сессий, журнал PowerShell.
- Журнал веб-сервера: признаки сканеров и серии ошибок доступа.
- На Astra — журнал аутентификации, сообщения ядра, `iptables` и `auditd`.
- Журнал Dr.Web, если продукт установлен.
- Снимок процессов, соединений, пользователей и слушающих портов.
- Дамп памяти выбранного процесса с контрольной суммой; файл скачивается из панели.

### Что обнаруживается и как реагирует

Политика задаётся в панели отдельно для каждого сервера и кэшируется у агента.

- Сканирование портов: быстрая серия, короткий всплеск и медленный обход. Реакция — тревога, инцидент и блокировка IP.
- Перебор паролей по неудачным входам с одного адреса.
- Веб-сканирование по признакам в журнале доступа.
- Поиск веб-шеллов в скриптах сайта по расписанию, без остановки связи с панелью. Повторно неоткрытые неизменённые файлы пропускаются.
- Фильтр по странам (GeoIP): тревога или блокировка адресов вне разрешённого списка.
- Оценка сессии баллами: незнакомый адрес, ночное окно, вход после серии неудач, разведывательные и разрушительные команды. Пороги ведут к тревоге, завершению сессии или блокировке адреса. Доверенные администраторы из политики не штрафуются.
- Белый список RDP: завершение сессий вне разрешённых адресов и учётных записей.
- Закрытие RPC Endpoint Mapper (порт 135) для адресов вне доверенных сетей, на Windows.
- Одинаковые блокировки за сканирование распространяются на остальные серверы через панель.
- Локальные адреса, адрес панели и явный белый список в детекторы сканирования не попадают.

Блокировка IP на Windows выполняется правилом брандмауэра, на Astra — средствами `iptables`. Срок блокировки ограничен. Снять её можно из панели, по истечении срока или добавлением адреса в белый список.

Если панель недоступна, агент продолжает проверки, применяет блокировки и складывает недоставленные события, инциденты, блокировки, PAM-записи и снимки в локальную очередь. После связи очередь отправляется автоматически. Служба перезапускается при зависании цикла и не сбрасывает токен при длительном офлайне.

На Astra отдельно от агента можно поставить Portspoof. Его порты-исключения задаются после установки агента, чтобы не задеть канал до панели.

## Защита самой панели

- Вход по паролю (bcrypt) и опциональный TOTP. После серии неудач адрес временно блокируется.
- Сессия оператора с привязкой к IP и отпечатку браузера. Экран блокируется вручную (Ctrl+L) и по таймауту бездействия.
- Журнал действий операторов и журнал событий — только добавление записей, со сцепкой хешей.
- Чувствительные поля (ФИО, секреты 2FA, текст событий и команд PAM) шифруются AES-256-GCM.
- База — PostgreSQL либо SQLite с SQLCipher. Для SQLite включены режим синхронизации на диск, резервные копии и восстановление после сбоя питания.
- TLS панели, сертификат CA для агентов, опциональная взаимная аутентификация. Токен агента на каждом запросе.
- Срок хранения журналов по умолчанию 90 дней, с ежедневной очисткой.
- Контроль целостности файла агента и признак отладчика.

Удалённая консоль на сервере из продукта убрана.

## Развёртывание

1. Установить панель: `installers/panel` (`install.ps1` или `install.sh`).
2. Открыть панель в браузере и завести администратора. Пароль по умолчанию и ключ JWT нужно сменить до работы в сети.
3. Указать адрес панели и поставить агент.
   - Windows Server 2012 и новее: `installers/agent` (`install_one.ps1`). Сборка под 2012 R2: `installers/agent/build.ps1 -Target ws2012r2`.
   - Astra Linux без доступа к репозиториям: подготовить офлайн-набор на машине с интернетом и запустить `agent-astra/install_one.sh`.
4. Агент регистрируется сам. Статус виден в разделе «Серверы».

Связь через WireGuard и смена адреса панели описаны в `installers/README.md` и `docs/USTANOVKA_AGENTOV.txt`.

Панель слушает порт **8443** (HTTPS). Приём syslog — порт **6514**. Адрес, который видят агенты, определяется автоматически или задаётся явно.

Переменные окружения панели имеют префикс `IMPERATIVE_` (файл `panel/backend/.env`): адрес БД, ключ сессий, ключ шифрования полей, порты, TLS, срок хранения журналов, лимит попыток входа.

## Обмен агента с панелью

| Вызов | Зачем |
| --- | --- |
| `POST /api/agent/register` | Регистрация, выдача токена |
| `POST /api/agent/heartbeat` | Метрики, команды и актуальная политика |
| `POST /api/agent/poll` | Частый опрос команд без полного цикла сбора |
| `POST /api/agent/events` | Пакет событий SIEM |
| `POST /api/agent/incident` | Инцидент |
| `POST /api/agent/ip-block` | Факт блокировки адреса |
| `POST /api/agent/forensic-snapshot` | Снимок состояния |
| `POST /api/agent/process-dumps` | Дамп процесса |
| `POST /api/agent/pam` | Сессии и команды привилегированного доступа |

Проверка живости панели: `GET /api/health`.
